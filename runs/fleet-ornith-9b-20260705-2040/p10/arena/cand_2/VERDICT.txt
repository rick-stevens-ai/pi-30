FIXED

Bug: off-by-one in sieve array size — `size = (n >> 1) + 1` allocates one extra slot when n is even. Index i represents odd number 2*i+1, so the largest valid index should be floor((n-1)/2). For n=10, this gives indices for odds {1,3,5,7,9} (size=5), but the code allocated size=6 including an extra slot for odd number 11. The sieve loop only marks composites up to sqrt(n), so index 5 (representing 11) is never touched and remains "prime", leaking it into output.

Fix: `size = (n - 1) // 2 + 1` — exact count of odd numbers in [1,n]. Verified correct for both even n=10 and odd n=11, plus edge cases n<2, n=2. All test cases pass.

No other bugs found:
- n<2 early-return is correct
- Even number 2 is handled separately (correctly)
- Slice-length formula `(size - 1 - start) // i + 1` is correct for Python slice semantics
